## 화면 확인 (스크린샷)

- 임시 PlayMode 테스트(`Assets/Tests/PlayMode/TempCapture.cs`, 커밋하지 않음)에서 캔버스를 ScreenSpaceCamera로 바꾸고
  RenderTexture 1080×1920을 PNG로 저장. 배치모드는 `-nographics` 없이 실행해야 그림이 나온다
- 캔버스 sortingOrder를 +1000 해야 필드 스프라이트가 UI 위에 찍히지 않는다 (캡처 때만 생기는 현상)
- 필드 화면은 Main Camera로, 나머지는 캡처용 카메라로 찍는다
- 실제 데이터로 찍기: `#if UNITY_EDITOR` 안에서 AssetDatabase로 GameDatabase·hero.asset을 불러 GameSession.NewGame → FieldScreen.Configure.
  비공개 창(altarView 등)은 리플렉션으로 열고, 길 열림 연출은 `RevealGates` 코루틴을 리플렉션으로 직접 실행
- 스크롤 목록은 배치모드 화면 크기(가로형)와 캡처 크기(1080×1920)가 달라서, 스크롤 위치는 캔버스를 캡처용으로 바꾼 '뒤'에 정해야 맞게 찍힌다

## 맵 그리기 (#23)

- 큰 맵은 손으로 글자를 치지 않고 스크래치의 파이썬 도우미로 그렸다: 캔버스를 '#'로 채우고 rect·ellipse·꺾은선 path·드문드문 나무(scatter)로
  깎아 냄 → 줄 길이·P 하나·모든 상자/샘/출입구 도달·도달 못 하는 걸을 칸 없음(탐험 %가 100이 되게)을 검사 → 실제 타일 PNG로 미리보기 렌더
- 세 맵 텍스트는 SampleDataBuilder 상수가 원본. 기존 에셋은 임시 에디터 스크립트로 map·chests를 바꾸고 Build + CreateAllScenes 실행 후 삭제
- 주의: bash heredoc 안의 파이썬에서 `\\n`이 실제 줄바꿈으로 바뀌는 일이 있었음 → C# 문자열에 `\n`이 들어가는 패치는 Write로 파이썬 파일을 만들어 실행

## 환경

- F: 드라이브 Git은 `safe.directory` 등록 필요 (`git config --global --add safe.directory F:/GameProject/WordRPG`)
- 빠른 컴파일 확인: 스크래치 csproj로 `dotnet build` (Unity DLL 참조) — 최종 확인은 Unity 배치모드 테스트
  - 만드는 법: 루트의 Unity가 만든 WordRPG*.csproj를 복사 → Compile 목록을 폴더 glob(`Assets\Scripts\**\*.cs`, Editor 제외)으로,
    상대 HintPath를 `F:\GameProject\WordRPG\` 기준 절대 경로로, 출력 폴더를 스크래치로 바꾼다 (새 파일이 csproj에 아직 없어도 됨)
- 사용자가 Unity 에디터를 열어 둔 채일 때 테스트: 프로젝트를 Library 없이 `F:\_WordRPG_testcopy`로 robocopy 해서 거기서 배치모드
  (첫 실행은 전체 가져오기라 몇 분 걸림. `F:\GameProject` 안에 두면 상위 저장소에 잡히므로 F: 바로 아래에)
  - 복사본에는 캡처용 `Assets/Tests/PlayMode/TempCapture.cs`(새 화면 PNG → `F:\_WordRPG_testcopy\captures`)가 있음. 다시 쓸 땐 robocopy /MIR 대신
    바뀐 파일만 복사하거나, /MIR 뒤 TempCapture.cs를 다시 넣을 것 (/MIR은 원본에 없는 파일을 지움)
- Unity 에디터가 프로젝트를 열고 있으면 배치모드 실행 불가 (`Temp/UnityLockfile` 확인)
